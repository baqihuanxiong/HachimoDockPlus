# NewAPI 阿里 RAM 自动令牌与板端验证

日期：2026-11-21，Asia/Shanghai。

## 结果

阿里 Token Plan 提供商支持 `auth: "access-key"`，从权限为 `600` 的独立单行 JSON 文件读取 RAM AccessKey。板端使用标准库实现 ACS3-HMAC-SHA256 签名和 `GenerateCLIAccessToken`，无需安装 CLI 或依赖电脑在线。原有手工控制台令牌配置保持兼容。配置方法见 [NewAPI 监控](../newapi-monitor.md#ram-自动获取与续期板端可独立运行)。

首次前台查询获取令牌，此后复用内存缓存；会话失效时按需换取并重试，每次刷新最多获取一次令牌。RAM 文件更换会废弃旧缓存。权限不足、网络错误和格式错误不会触发反复续期。离开页面取消网络请求与等待，再次进入继续按需查询；没有离开后遗留的续期任务或磁盘令牌缓存。RAM JSON 同时纳入配置共享应用前的无网络校验。

## 主机验证

- 全仓 `go test -race -p 2 -tags stdjson,goolm ./...`、`go vet -tags stdjson,goolm ./...` 通过。
- 固定签名向量由独立 Python hashlib/hmac 计算，与 Go ACS3 签名完全匹配。
- 回归覆盖首次获取、缓存、过期后单次重试、新令牌仍失效时停止、HTTP 401/403、业务空间及页面权限不足、令牌接口拒绝与格式错误、密钥轮换、并发共用令牌、等待取消和网络取消。
- 配置回归覆盖旧配置兼容、仅阿里支持此鉴权、官方 HTTPS 网关与地域匹配、RAM JSON 格式及安全错误。新加坡与 STS 签名路径通过模拟请求验证，未使用海外真实账号。
- 显式启用 `TestLiveAliyunAccessKeyReadOnly`，使用实际 RAM 凭证经新增 Go 实现连续查询两次，均返回约 56.0% 月度剩余额度。没有调用模型推理或 NewAPI 写接口。
- ARM 构建通过，差异空白检查通过；本次没有更改页面布局。

## 板端验证与安装

设备为 `root@192.168.4.202`，Lyra Zero W / RK3506B / ARMv7。正式服务暂停后，先在 `/tmp` 用候选 ARM 程序及独立配置、独立数据目录运行终端页面；主网关及上游额度保持真实只读查询，连续两次刷新均返回阿里月度剩余 56.0%。临时配置中未启用桌宠 LAN，未改动用户配对。

由于 NAND 余量不能同时容纳两份约 24 MiB 程序，先把旧程序复制到 `/tmp` 并核验哈希，再安装新版本；部署脚本包含异常回退。完成后清理临时程序、密钥、数据目录和内存回退副本，恢复正式监督服务。

只将阿里提供商改为 `auth: "access-key"` / `key_file: "secrets/aliyun-ram.key"`，分别最小合并到生效配置及 SMB 待应用配置；RAM 文件安装到两处，权限均为 `600`，内容一致。未把其他待编辑设置整体应用。部署前后对其他既有密钥及应用数据逐文件核对哈希，保持一致。

正式服务中通过真实 evdev 注入进入 NewAPI 页面，确认阿里余额为 56.0%，MiMo 与日／周／月统计正常，并验证手动刷新和返回后重新进入。此操作只覆盖自动输入事件，不等同人工面板触摸验收。没有发送任何真实用户余额重置请求。
