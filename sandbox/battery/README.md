# 电池电压与电流测试

适用 Lyra Zero W / RK3506B、Linux 6.1.99、Buildroot。脚本 [battery_probe.py](battery_probe.py) 只依赖 Python 3 标准库，通过 `/dev/i2c-2` 读取 INA226；已在 `root@192.168.4.202` 上验证。无需安装驱动、Python 包或修改固件。

## 接线与换算

依据 [2026-11-07 底板原理图](../../hardware/SCH_底板_2026-11-07.pdf) 第 1 页：

| 项目 | 连接 / 数值 |
|---|---|
| INA226 | U10，A0/A1 接地，7 位地址 `0x40`，3.3 V 供电 |
| SDA / SCL | I²C2，核心板 PI1 pin 3/5，底板 U2 pin 4/6 |
| 采样电阻 | 本次 PDF 标为 **U11，10 mΩ**；旧审查记录称为 R20 |
| IN+ | `VBAT_IN+`，电池开关 U9 后、电阻电池侧 |
| IN− | `VBAT_IN-`，电阻系统侧，与 `VBAT` 相连 |
| VBUS | 经 R19（100 Ω）接 `VBAT`，C38（100 nF）滤波 |

电流为正表示放电，为负表示充电。`VBUS` 是电阻系统侧电压；脚本的 `Vbat~` / `battery_side_v` 为 `VBUS + I × 0.01 Ω`，估算的是电池开关后、采样电阻电池侧电压，不含电池接头、导线和开关上的压降。

寄存器换算依据 [TI INA226 数据手册](https://www.ti.com/lit/ds/symlink/ina226.pdf)：

- 电压：`0x02 × 1.25 mV`；采样压降：`int16(0x01) × 2.5 µV`。
- 临时设置校准寄存器 `0x05 = 0x0800`，对应 `Current_LSB = 0.25 mA`、电流 `int16(0x04) × 0.25 mA`。此时电流和采样压降寄存器的有符号原始值应相同，脚本逐组交叉检查。
- 每组写配置 `0x00 = 0x4523`：电压与电流各 1.1 ms、16 次平均、单次触发，总转换时间约 35.2 ms。等待 `0x06` 的 CVRF（bit 3）后读取稳定的一组寄存器，超时 0.5 秒或 OVF（bit 2）置位则退出报错。
- 带符号功率 `P = VBUS × I`，负值表示充电功率。JSON 另保留芯片 `0x03` 的原始值；不将该无符号功率寄存器直接作为带符号功率。

绝对电流小于等于 5 mA 时显示 `IDLE`，这只是显示阈值，未判断充电器的状态。脚本不估算电量百分比、容量、剩余时间或充满状态；这些需要电池参数及额外验证。

## 运行

从项目根目录上传，再读取 10 组：

```sh
scp -O sandbox/battery/battery_probe.py root@192.168.4.202:/tmp/battery_probe.py
ssh root@192.168.4.202 'python3 /tmp/battery_probe.py --count 10'
```

实时显示，每秒一组，Ctrl+C 退出：

```sh
ssh -t root@192.168.4.202 'python3 /tmp/battery_probe.py'
```

默认 `/dev/i2c-2`、`0x40`，可通过 `--i2c`、`--address` 指定。`--interval` 为采样起点间隔（秒），最小 0.05；实际速度受转换及系统调度影响。`--count 0`（默认）持续运行。

保存原始寄存器与换算结果为 JSON Lines：

```sh
ssh root@192.168.4.202 'python3 /tmp/battery_probe.py --count 30 --interval 1 --json' \
  > /tmp/battery-measurement.jsonl
```

输出示例（实测）：

```text
[   0.056] CHARGING    VBUS=4.17500 V Vbat~=4.16888 V I=-611.50 mA P=-2.5530 W Vshunt=-6.1150 mV
```

`INIT` / `RESTORED` 的寄存器数值以及 JSON `raw` 为十进制；时间为脚本启动后的单调时钟秒数。JSON `power_w` 为上述带符号计算值。

启动时校验制造商 `0x5449` 和芯片 ID `0x226x`，仅访问指定地址，不扫描总线或广播复位；内核驱动占用地址时拒绝访问，不强制抢占。进程持有 I²C 设备文件的独占建议锁，重复启动本脚本会退出。其他程序须配合锁或避免同时配置 `0x40`；锁不会阻止不遵守它的程序。

正常结束、Ctrl+C、SIGTERM 和读取错误均会尝试恢复启动前的配置及校准值，并读回确认。读取 `0x06` 会清除 CVRF 等状态标志，原配置的转换时序也会重新开始。SIGKILL、断电或通信故障不能保证恢复。重新上电后校准寄存器默认为零；正式应用需要自行初始化。

## 实机验证记录

2026-11-14，电池开关已打开，Python 3.11.8，`/dev/i2c-2@0x40`：制造商 `0x5449`、芯片 ID `0x2260`，启动前配置 `0x4127`、校准 `0x0000`。本次未切换电池开关或插拔供电。

[连续采样原始记录](measurement-2026-11-14.jsonl) 含 30 组有效数据，采样间隔 1 秒，首末样本相隔约 29 秒：

| 测量项 | 最小值 | 最大值 | 平均值 |
|---|---:|---:|---:|
| VBUS | 4.17500 V | 4.17625 V | 4.17554 V |
| 电池侧估算电压 | 4.16895 V | 4.17027 V | 4.16952 V |
| 电流 | −606.00 mA | −597.50 mA | −601.74 mA |
| 带符号功率 | −2.53081 W | −2.49456 W | −2.51260 W |

全部为 `CHARGING`，CVRF 正常、OVF 未置位；电流与采样压降的原始值逐组相同。定量精度尚未用万用表或标准电流负载校准。

定量采样完成后，配置/校准恢复为 `0x4127` / `0x0000`；另实测重复进程被拒绝、SIGTERM 正常退出并恢复，随后用 `i2cget` 独立读回确认。注意 `i2cget ... w` 按 SMBus 字节序显示配置为 `0x2741`，换回 INA226 大端顺序才是 `0x4127`。

主机已检查 Python 语法、有符号正负电流、补偿电压、异常数据拒绝和模拟读取失败时的配置恢复。放电方向和充放电切换尚未实机验证：后续保持电池开关打开，在电池可独立供电的条件下移除外部充电输入，检查读数是否转为正；接回后检查是否转负。需以实际电池和供电状态为准。

## 主程序状态栏接入

`src/internal/platform/battery` 使用相同 INA226 寄存器和换算参数，每三秒触发一次测量，结束后恢复原配置与校准。它配合本脚本的 `/dev/i2c-2` 建议锁，争用时本轮显示不可用并等待下次采样，不强制抢占。需要独占测试时，先执行 `/etc/init.d/S99hachimodock stop`，测试完成再执行 `start`。

初版状态栏显示补偿后的电池侧电压，电流低于 −5 mA 时显示充电标识；当时未换算百分比。自动测试覆盖正负电流、异常读数、身份校验，以及采样失败、取消时恢复配置与校准。

2026-11-14 状态栏版本完成主机竞态测试、`go vet`、原生 LVGL 测试与 ARM 构建，已部署至开发板。实屏显示北京时间、约 4.19 V 和充电标识，Wi-Fi 已连接显示绿色，蓝牙关闭后变灰、开启后恢复蓝色。参考脚本在部署前测得电池侧 4.18932 V / −568.25 mA；Go 采样运行并停止后，参考脚本再次读到配置 `0x4127`、校准 `0x0000`，与部署前一致。两次读取时间不同，不作为精度校准对比。日志与截图位于 `src/build/header-*`。

后续按单行状态栏需求改为只显示电池图标，隐藏电压和数字。图标填充及绿（≥20）、橙（10～19）、红（<10）颜色使用普通 4.2 V 单节锂电池的默认电压曲线粗估；完整曲线见 [应用说明](../../src/README.md)。尚未对当前电芯标定，充电和负载会影响判断，不作为实际容量测量。增加了估算边界、单调性、异常电压测试，原生 LVGL 测试覆盖三档颜色、未知状态与充电标识。
